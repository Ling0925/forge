为什么是 Forge

不做云托管代理，也不做黑盒自动化。它把代理能力装进你自己的机器，并把审查权留在你手上。

⇄

双端一体，共享核心

桌面创建的会话可用 forge resume <uuid> 在终端无缝接续，反向同理。配置、状态与工具管道完全共享。

🛡

分级权限与逐项审批

readonly / workspace / unrestricted 三档策略；命令执行与文件改动支持逐项审查，拒绝黑盒盲跑。

⏪

文件级检查点

对 write_file / edit_file 的每次直接改动生成安全快照，支持单文件差异核对与带冲突保护的回滚。

🤖

受限子代理协作

原生 spawn_agent：最大深度 1、并发 ≤ 4 的独立子任务调度；子代理严格继承父级权限上限。

🔌

原生工具与 stdio MCP

内置文件/系统工具与只读 Git 观测（git_status / git_diff / git_log），并支持标准 stdio MCP 扩展。

🎯

精确模型发现

list_models 实时列出当前 Provider 的精确模型 ID，支持子串过滤与分页，从源头避免虚构模型。

桌面端适合长任务、检查面板与审批流；终端适合快速起停、脚本化与远程机器。二者不是两个产品。

权限模型与诚实边界

先说清楚能做什么，也先说清楚不做什么。

模式读文件写文件执行命令适用场景
readonly✓—— 代码审阅、架构分析、排查定位
workspace 推荐✓ ✓ 仅工作区⚠ 逐项审批 常规功能开发与本地重构
unrestricted✓✓ ⚠ 仍需审批* 受信任环境、自动化批处理

* 除非显式指定 --yes，命令执行仍会逐项征求确认。

我们不夸大安全性

不是操作系统沙箱。命令一旦获批准，将以宿主当前用户权限运行，可访问工作区之外的文件与网络。

检查点范围有限。仅自动覆盖 write_file / edit_file 的直接改动，不捕获 run_command 产生的副作用。

MCP 仅支持 stdio。注册后默认禁用，必须显式启用，且每次调用仍需确认。

不伪造指标。只有 Provider 协议真实返回 Token 与缓存统计时才展示，不推断、不编造命中率。

快速上手

Linux x64；CLI 需 Node ≥22.23.1 <23，桌面发布包已内置 Electron。

# 配置兼容 Provider（密钥经 stdin 注入，不落 argv / 历史记录）
forge config set --base-url https://example.invalid/v1 --model example-model
printf '%s' "$MY_PROVIDER_KEY" | forge config set --api-key-stdin

# 查询该 Endpoint 真实可用的模型 ID
forge models

# 只读分析：梳理项目结构与入口
forge run '梳理本项目的目录结构与入口文件' --workspace . --permission readonly

# 交互构建：修 bug 并跑测试
forge run '修复 tests/math.test.ts 中失败的用例' --workspace . --permission workspace

# 历史会话：列出 / 续接 / 分支 / 语义压缩
forge sessions
forge resume <session-uuid>
forge fork <session-uuid>
forge compact <session-uuid>
