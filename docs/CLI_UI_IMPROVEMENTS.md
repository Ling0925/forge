# Forge CLI 界面实现分析与优化方案

本文档对当前 Forge CLI（终端 TUI / 交互界面）的实现架构进行系统性分析，记录经源码核对的现状、设计优势、体验缺口与具体的优化改进方案。

- 适用范围：`src/cli/terminal/**`、`src/cli/render/**`、`src/cli/**`
- 相关规范与契约：[CLI.md](CLI.md)、[MARKDOWN_REQUIREMENTS.md](MARKDOWN_REQUIREMENTS.md)、`src/cli/ui-contract.ts`

---

## 1. 当前架构与设计优势

经过代码核对，当前 Forge CLI 已经拥有非常高水准且现代化的 TUI 基础架构：

1. **完备的现代终端协议栈**：
   - **Alternate Screen** (`\x1b[?1049h`)：独立全屏视口，退出后干净恢复原 shell 历史。
   - **Bracketed Paste** (`\x1b[?2004h`)：精确区分粘贴文本与键盘单键输入，防止回车误触。
   - **SGR 扩展鼠标模式** (`\x1b[?1002h\x1b[?1006h`)：支持视口滚轮滚动与选区拖拽高亮。
   - **Synchronized Output** (`\x1b[?2026h`)：在 `screen.writeFixed` 帧绘制时使用同步标记，根除高频刷新下的撕裂和闪烁。
2. **高效的增量渲染机制（Delta Painting）**：
   - `Screen.paint` 维护了逻辑行缓存与真实输出差异比对，仅移动光标（`\x1b[row;colH`）擦除并重绘实际发生变动的行，极大降低终端 I/O 消耗。
3. **字素级排版与宽字符/Emoji 准确度**：
   - 依赖 `Intl.Segmenter` 对字符做字素簇（Grapheme Clusters）拆分；
   - 包含 East Asian Width 算法计算真实列宽，保证光标在 CJK 中文字符、全角标点、Emoji 上的移动与物理终端完全对齐。
4. **创新的多维度上下文进度条（Context Footer）**：
   - 按指令（Instructions）、记忆（Memory）、对话（Conversation）、工具（Tools）四色分段渲染 token 占比，并在右侧标记压缩警戒红线，信息密度与视觉层级高。
5. **严密的内容净化与信任边界**：
   - 所有模型输出、工具结果在渲染前均通过 `ControlFilter` 过滤危险的 CSI/OSC 控制序列，只有内部控制器有权输出受控样式。

## 2. 现存体验缺口与优化点

经过对各子模块的深入排查，梳理出以下 4 个维度共 12 项优化点：

### 2.1 视口滚动与历史回溯（Scroll & Viewport UX）

* **缺口 1：向上翻看历史时，缺少滚动状态提示与一键回到底部**
  * **现状**：`src/cli/terminal/screen.ts` 在 `scrollOffset > 0` 且收到新流式内容时，会自动递增 offset 以保持当前浏览视口固定，这是很好的设计。但界面上**没有任何视觉线索**提示用户“当前停留在历史中，下方有新输出”，也没有快捷键一键跳回最新位置。目前只能通过多次按 `PageDown` 或向下滚轮慢慢滑回。
  * **优化方案**：
    1. 当 `scrollOffset > 0` 时，在视口右下方或状态行显示微标，如 `▼ 正在浏览历史 (距底部 N 行) · Esc/End 到底部`；
    2. 在 `keys.ts` 中支持：当处于浏览历史状态时，按 `End` 键（或在输入框无内容时按 `Esc`）触发 `screen.scroll(-Infinity)`，一键平滑归位到最新会话底部。

* **缺口 2：OSC 52 剪贴板复制缺乏交互反馈与系统剪贴板降级**
  * **现状**：鼠标拖选文字后，按 `Ctrl+C` 发送 `\x1b]52;c;<base64>\x07`。但在很多终端（如 macOS 默认 Terminal.app、未开启 `allow-set-clipboard` 的 tmux、部分 Linux 默认终端）中，OSC 52 会被静默忽略。用户按下后既不知道是否成功，也无法得知剪贴板为何为空。
  * **优化方案**：
    1. **视觉反馈**：按复制键后，选区短暂高亮闪烁或在状态行显示 `✓ 已复制 N 行`（1.5 秒后自动淡出恢复原状态）；
    2. **本地降级方案**：如果终端未响应或配置不支持，可考虑以无阻塞方式尝试管道写入系统剪贴板命令（`pbcopy` / `wl-copy` / `xclip`）。

* **缺口 3：缺少终端必备的清屏重绘快捷键（`Ctrl+L`）**
  * **现状**：当终端因外部异常输出（如子进程偶发未重定向的 stderr）或窗口异常伸缩导致终端物理画面错乱时，用户无法主动重置界面。
  * **优化方案**：在 `decoder.ts` 捕获 `\x0c`（`Ctrl+L`），绑定 `screen.invalidate()` 触发全屏擦除与完整重绘。

### 2.2 输入框与编辑器交互（Composer & Editor）

* **缺口 4：底部 Dock 最大 10 行硬编码限制（响应式高度缺位）**
  * **现状**：`src/cli/terminal/view.ts` 第 36 行：
    ```ts
    const limit = Math.max(1, Math.min(10, view.rows - 1));
    ```
    无论是 24 行的小窗口还是 60 行的大显示器，底部输入区、Picker（`/model`、`/resume`）以及 Slash 菜单总行数都被限制在 10 行以内。扣除 footer（2 行）、pending/status（1-2 行）、输入框（1-2 行）后，留给列表的行数往往仅剩 3~4 行。
  * **优化方案**：
    根据当前视口高度 `view.rows` 动态计算 Dock 上限，如 `Math.max(1, Math.min(Math.floor(view.rows * 0.45), 20, view.rows - 2))`。在大窗口下让选择器和菜单展示 8~12 项，大幅减少翻页频次。

* **缺口 5：多行输入的换行易用性（规避 Shift+Enter 误发送）**
  * **现状**：多行输入目前依赖行尾输入反斜杠 `\` 后按回车，或按 `Shift+Enter`。但大多数普通终端模拟器默认不启用扩展键位协议，会将 `Shift+Enter` 作为普通 `\r` 提交，导致多行输入时极易误发。
  * **优化方案**：
    1. 增加终端通用按键支持：支持 `Alt+Enter`（`\x1b\r`）作为确定换行按键；
    2. 支持长文本编辑快捷指令（例如 `/edit` 临时唤起系统 `$EDITOR` 或内置多行缓冲）。

* **缺口 6：补齐常用 Readline / Emacs 行编辑动作**
  * **现状**：
    - `editor.ts` 中的 `kill`（绑定 `Ctrl+U`）直接重置光标为 0，清除了光标前所有多行内容，而非当前物理行的行首；
    - 缺少 `Ctrl+K`（剪切光标到当前行尾）；
    - 缺少 `Alt+B` / `Alt+F`（按单词前进/后退光标）。
  * **优化方案**：
    规范化行编辑快捷键，让多行输入下的 `Ctrl+U`/`Ctrl+K` 遵从单行边界，并加入基础单词移动。

* **缺口 7：提示词历史记录（Prompt History）跨进程持久化**
  * **现状**：`Editor` 的历史输入记录仅保存在内存实例中，退出 CLI 或新开会话后，按 `↑` 无法回忆之前输入过的 Prompt。
  * **优化方案**：将输入历史记录持久化至本地环境目录（如 `~/.forge/history`，限制 1000 条），新进程启动时加载，并在提交输入后静默更新。

### 2.3 内容渲染与视觉层次（Markdown & Diff Rendering）

* **缺口 8：代码块（Code Block）缺失边框与语言标识**
  * **现状**：`src/cli/render/markdown.ts` 中遇到围栏行 ````lang` 时，静默跳过该行，代码块正文直接输出，导致代码块与普通正文段落之间缺少明确的分界线和语言标记。
  * **优化方案**：
    为代码块渲染轻量级边框线与语言标签：
    ```text
    ┌─ typescript ──────────────────────────────────────────────
    │  export function execute(command: string): void {
    │    console.log("running:", command);
    │  }
    └───────────────────────────────────────────────────────────
    ```
    既不依赖 ANSI 背景色，又能在各种终端背景下形成清晰的视觉层级。

* **缺口 9：代码块轻量语法着色**
  * **现状**：代码块内部目前只对十几个关键字进行了高亮（全染为单一 accent 色），注释、字符串、数字、符号均无着色。
  * **优化方案**：在保持轻量化（零第三方重量依赖）的前提下，补充 3 条核心规则：
    - 注释（`// ...`、`# ...`、`/* ... */`）着 `muted` 色；
    - 字符串（`"..."`、`'...'`、`\`...\``）着特定次高亮色（如 `success` 或特定色彩）；
    - 数字与布尔值适度区分。

* **缺口 10：Diff 视图头部增加变更统计徽章**
  * **现状**：`src/cli/render/diff.ts` 已支持统一差异渲染与 Myers edit script，非常精准。
  * **优化方案**：在文件路径上方或同行添加紧凑的统计标签，如 `src/cli/view.ts [+18 -4]`，方便多文件变动时快速定位变更量。

### 2.4 状态反馈与极端窗口适配（Context & Terminal Adaptation）

* **缺口 11：小窗口下的 Context Footer 紧凑模式（Compact Footer）**
  * **现状**：`contextFooter` 强制占用 2 行（第一行模型与百分比，第二行四色进度条）。当终端高度低于 20 行时，两行 footer + status + input 会占掉几乎半个屏幕。
  * **优化方案**：
    当 `view.rows <= 20` 时启用单行紧凑模式：左侧显示模型名，右侧显示压缩百分比和一段缩短的迷你条，为正文历史留出更多显示行。

* **缺口 12：窗口快速调整（Resize）时的微防抖**
  * **现状**：收到 `SIGWINCH` 信号时立刻调用 `screen.invalidate()` 重绘。在连续拖拽窗口边缘时，每秒触发数十次全屏刷新，可能导致短暂停顿或局部残影。
  * **优化方案**：
    对终端尺寸变化引入约 16ms（约一帧）的防抖等待，待几何尺寸稳定后再进行布局重排与屏幕重绘。

## 3. 优先级与落地建议

| 优先级 | 优化项目 | 核心价值 | 改动范围 |
| :--- | :--- | :--- | :--- |
| **P0（高感知）** | **滚动历史提示 + 一键直达底部（Esc/End）** | 消除用户对“是否有新输出”的不确定感，大幅降低翻页操作成本 | `screen.ts`, `keys.ts`, `view.ts` |
| **P0（高感知）** | **代码块（Code Block）边框与语言标识** | 解决代码与正文混杂、边界不清的问题，显著提升长回复阅读舒适度 | `render/markdown.ts` |
| **P1（体验）** | **底部 Dock 高度响应式自适应** | 充分利用宽屏/高屏终端，提升 Picker 与 Slash 菜单项检索效率 | `terminal/view.ts` |
| **P1（体验）** | **多行换行增强（Alt+Enter）与 `Ctrl+L` 清屏重绘** | 解决 Shift+Enter 误发痛点，补齐终端必备的抗错重绘手段 | `decoder.ts`, `keys.ts` |
| **P2（锦上添花）** | **复制成功反馈、代码块多色高亮、Diff 变更统计** | 进一步提升细节质感，消除剪贴板操作无响应疑虑 | `render/**`, `theme.ts` |
| **P2（长期）** | **Prompt 历史记录本地持久化** | 跨进程保留用户输入习惯 | `terminal/editor.ts`, `store/**` |

## 4. 本轮落地与未完成项（2026-10-14）

已实现：无计划占用状态位时显示历史距底部行数，End 或空草稿 Esc 回到底部；Ctrl+L 强制重绘；Alt+Enter 字面换行（审批/picker 不触发）；Ctrl+U 仅删除当前行光标前文本，Ctrl+K 删除至当前行尾，Alt+B/F 按词移动。审批、粘贴、普通 Enter/Shift+Enter 语义保持。原方案 §2.2 把 Shift+Enter 写为换行并不准确：本项目运行时它是 steer，未改写此契约。

上述为第一批记录；剩余功能的后续实施见 §5，不应再将第一批待办表当作当前完成状态。

## 5. 后续实现与边界（2026-10-15）

**更新**：本节手写代码框/高亮方案已被用户后续要求替换。当前 CLI 使用 marked + marked-terminal + cli-highlight，代码语言分隔线/缩进、GFM 表格、整段流式重排的实际契约及检查见 `MARKDOWN_REQUIREMENTS.md` §12；不再维护手写 Markdown 语法。

- **代码块**：CLI 围栏显示语言标签、左侧边框与结束线；支持反引号/波浪线围栏及匹配的闭合长度，未闭合时明确标记。JS/TS、JSON、Python、Shell、CSS 及若干类 C 语言使用本地轻量词法着色（关键字、字符串、数字、注释）；未知语言纯文本。行长度 60000、token 8000 上限降级保留原文。不是完整语法解析器；多行模板/字符串等复杂语法不保证着色准确。控制序列仍先过滤，不生成模型提供的转义。流式未完成行暂按纯文本，提交后着色。
- **Diff 统计**：头部显示 `[+N -M]`，对应当前 diff 编辑脚本；上游内容截断时标注 `partial preview`，未知原文不编造计数。算法降级的全量替换脚本计数也不等于最小 diff。
- **响应式 Dock**：预算随终端高度增长，最多 20 行；低窗口保留最小可用空间，高窗口菜单最多 12 项。菜单打开时隐藏 footer，为输入和选项让位；不强行填充全部预算。输入行、审批优先。
- **紧凑 Footer**：高度 ≤20 行使用单行模型、窗口占用/总量，宽度允许时增加 6 格迷你进度条；极窄/矮窗口缩略或隐藏。高窗口保留原分类双行条。
- **Resize**：16ms 固定窗口合并，连续事件不无限延迟；立即废弃旧选区，期间推迟普通重绘，审批开始可立即刷新；dispose 清理定时器。
- **复制反馈**：Ctrl+C 复制选区后释放选区并显示 1.5 秒 `Clipboard request sent (OSC 52); terminal support required`。只证明请求已发送，不宣称 OS 剪贴板成功。空/过大选区明确提示未发送。不自动启动 pbcopy/wl-copy/xclip（这是可选替代，不是必须项）。
- **跨进程历史**：`/history on|off|clear|status`；默认 off，每个 CLI 进程显式启用后加载旧历史，按工作区 realpath 哈希隔离。每工作区 ≤1000 条、JSON ≤1 MB、单条 ≤16000 字符，目录 0700、文件 0600，原子写与锁内读改写；冲突/失败暂停并提示、不自动重试。排除审批答案、slash 命令、首字符空白与常见秘密模式，不能识别所有秘密。退出等待已排队写入；清除只清当前工作区历史，不删除会话。Linux flock 为既有存储前提。
- **接线修复**：此前 Controller 已有 setMode/onModeToggle/setPlan，但 TerminalReader.ui 未转发。现已补齐，真实 Reader 的 CSI Z 与计划渲染覆盖于新增回归。
