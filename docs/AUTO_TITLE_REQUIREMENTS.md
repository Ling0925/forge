# Forge 会话自动命名需求

本文是**会话自动命名**的需求文档，覆盖桌面工作台与 CLI 两个入口。
它描述目标行为、现行实现、集成点、待决问题与验收标准，**不是**已通过验收的声明。

- 相关契约：[ARCHITECTURE.md](ARCHITECTURE.md)（会话与事件）、[CLI.md](CLI.md)、[WORKFLOWS.md](WORKFLOWS.md)、[DESIGN.md](../DESIGN.md)。
- 术语：**自动命名**指在无需用户手动操作的情况下，根据会话内容生成并写入会话标题（`title`）。
- 区分：**手动重命名**已存在（`renameSession`）；本需求新增的是**自动**命名。

## 1 背景与现状（经代码核对）

当前**不存在**任何"根据对话内容自动生成标题"的能力。现有标题来源是被动的：

| 入口 / 场景 | 现状 | 位置 |
| --- | --- | --- |
| 桌面新建 | 取**用户首条输入前 80 字符**（机械截取，非语义命名，且在**运行前**定好） | `src/renderer/components/workbench/Composer.tsx:172` |
| CLI 启动 | **不传标题** → 落回硬编码 `"New session"` | `src/cli/interactive.ts:66` → `src/core/harness.ts:462` |
| CLI `/new` | **不传标题** → 同样 `"New session"` | `src/cli/interactive.ts:455-459` |
| 子代理会话 | 取 `spawn_agent` 的 `task` 前 256 字 | `src/core/agents.ts:243` |
| Fork | `Fork: 源标题` | `src/core/harness.ts:284` |

关键事实：

- **标题 schema**：`title: z.string().min(1).max(256)`（`src/shared/schemas.ts:478`，`summaryFields`）。
- **手动重命名**：`renameSession(id, title)` → `mutate` → 保存（`src/core/harness.ts:304`）。注意其实现用 `settingsFields.model.parse(title)` 校验标题（**复用模型字段 schema**，见 §8 风险）。
- **无标题变更事件**：现有事件类型为 `run_started`、`text_delta`、`tool_started`、`tool_finished`、`approval_requested`、`state_changed`、`plan_updated`、`agent_update`、`context_compacted`、`error`、`run_finished`（`src/shared/schemas.ts:380-475`）。**没有任何** `title_updated` 类事件。
- **UI 刷新**：渲染端在 `run_finished` 时刷新（`src/renderer/state/workbench-context.tsx:130`），并通过 `listSessions`（`:84`）拉取列表；侧栏直接读 `session.title`（`Sidebar.tsx:149`）。
- **CLI 回退**：`format.ts:278` 有 `session.title || "未命名"` 兜底，但因 title 为 `min(1)`，该分支**实际不可达**。

结论：**桌面有"首轮截断"这一弱替代品，CLI 完全没有**，两端都**无**语义级自动命名。

## 2 目标

1. 会话在**首轮有意义的交互后**，自动获得一个**简洁、可读、反映任务内容**的标题。
2. 自动命名**不得覆盖**用户已手动设置的标题。
3. 自动命名**失败或不可用**时**安全降级**，绝不阻塞运行、绝不丢失会话。
4. 两端（桌面 / CLI）行为**一致**，命名结果在任一入口都可见。

## 3 非目标

- 不自动重命名**用户已手动改过**的标题。
- 不在**每一轮**都重新命名；命名是低频的、有节制的。
- 不引入远端服务或额外凭据；命名若用模型，须复用**已配置**的 provider。
- 不改变 `title` 的 schema 约束（`min(1)`/`max(256)`）。
- 不改变 Fork / 子代理的既有命名规则（除非另开需求）。

## 4 功能需求

### 4.1 触发时机（R-T 系列）

- **R-T1**：触发点为**首轮运行结束**（`run_finished`）后，且仅当会话**仍在使用默认/占位标题**时执行一次。
  - 建议"仍是默认标题"判定：标题等于创建时的初始值（`"New session"` 或首轮截断结果），且 `contextSummary`/消息数表明已有真实对话。
- **R-T2**：每个会话**最多自动命名一次**。需要持久化"是否已自动命名"的标记，避免重启后重复命名。
- **R-T3**：首轮**失败/取消/中断**（`run_finished.status !== "completed"`）时是否命名，需明确（见 §7 Q2）。默认建议：仅 `completed` 时命名，`failed` 可不命名。
- **R-T4**：若首轮内容不足（如用户只发了 `"hi"`），允许**不命名**或退化为启发式，不得产出无意义标题。
- **R-T5**：自动命名必须**在会话锁内**完成，不得与活动运行争用（参照 `mutate` 的锁语义，`src/core/harness.ts:214`）。

### 4.2 生成方式（R-G 系列）

- **R-G1**：优先**基于模型**生成：复用已配置 provider 的 `complete(...)`（`src/shared/contracts.ts:33`），输入为**首轮用户输入 + 助手回复摘要**，输出一个短标题。
- **R-G2**：标题约束：非空、单行、≤ N 字符（建议 40–60，最终写入前 `slice` 到 ≤256 以满足 schema）。
- **R-G3**：命名请求必须有**独立 30 秒超时**，超时即降级；仍响应调用方取消与根运行预算截止，**不得**因命名失败影响会话状态。
- **R-G4**：命名请求**不得**写入会话消息历史、**不得**计入 `maxTurns`/`maxToolCalls` 预算（它是元数据，不是对话轮次）。
- **R-G5**：命名请求**不得**包含密钥或私有配置；输出须经 sanitize（去除换行、控制字符、多余引号）。
- **R-G6（降级路径）**：模型不可用/未配置/超时/输出非法时，退化为**本地启发式**：取首轮用户输入的首行、截断到上限、去除 Markdown 标记与前导空白。若启发式结果为空，则保留原占位标题。

### 4.3 覆盖与共存（R-O 系列）

- **R-O1**：**不得覆盖**用户手动设置的标题；需要可靠的"用户是否改过标题"判定（见 §7 Q1）。
- **R-O2**：自动命名与手动 `renameSession` 使用**同一存储字段与同一校验**，避免两套真相。
- **R-O3**：自动命名结果应可被用户随后手动覆盖，且覆盖后不再被自动改写。

### 4.4 可见性与事件（R-V 系列）

- **R-V1**：命名结果必须在**两个入口**都可见：
  - 桌面：侧栏会话项（`Sidebar.tsx:149`）在下次刷新时显示新标题。
  - CLI：`forge sessions` 列表（`cli.ts`）与 `/sessions` picker 显示新标题。
- **R-V2**：需要**明确的更新通知机制**（见 §7 Q3）：
  - 方案 ①：新增 `title_updated` 事件类型（需扩展 `agentEventSchema`）。
  - 方案 ②：复用现有 `state_changed` 之外的无事件路径——由宿主在 `run_finished` 后重新拉取会话快照。
  - 需求倾向**方案 ①**（明确、可观测），但需评估对事件 schema 与既有测试的兼容成本。
- **R-V3**：命名是**后台元数据操作**，**不得**打断或延迟 `run_finished` 的终态语义；建议在终态之后异步执行。

## 6 安全与边界约束（强制）

- **R-X1**：**不得阻塞**主运行循环；命名失败不得导致 `run_finished` 变 `failed`。
- **R-X2**：命名请求**不得**越过当前会话的权限语义（它是只读元数据操作，不触发工具执行）。
- **R-X3**：**不得**把命名请求的输入/输出写入会话 `messages` 或 `events` 正文（除标题本身与可选的事件）。
- **R-X4**：**不得**记录密钥、端点或私有配置到标题或日志。
- **R-X5**：标题输出必须做 sanitize：去换行/控制字符、去首尾引号、限制长度。
- **R-X6**：**不得**因命名而额外产生**不可控**的网络成本；需有超时与"仅一次"双重约束。

## 7 待决问题

- **Q1（关键）**：如何判定"用户是否已手动改过标题"？
  - 方案 a：新增持久化标记（如 `titleSource: "auto" | "user" | "default"`）——最可靠，但需扩展 schema。
  - 方案 b：比较标题与创建时的初始值——不精确（用户可能改成相同值）。
  - 建议：**方案 a**。
- **Q2**：首轮 `failed`/`cancelled` 时是否命名？
- **Q3**：更新通知用**新增事件**还是**宿主重拉**？（影响 schema 兼容与测试）
- **Q4**：命名用**独立模型**还是**当前会话模型**？（当前模型可能不可用或昂贵）
- **Q5**：CLI 与桌面是否都需要首轮**立即**命名，还是允许**下次列表刷新**时才显示？
- **Q6**：命名语言：跟随用户输入语言，还是固定中文/英文？
- **Q7**：`/new` 与 `forge run` 的非交互路径是否也自动命名？

## 8 风险与约束

- **锁与并发**：自动命名需在会话锁内进行；若与用户操作（如重命名、运行）并发，必须有明确优先级与重试/放弃策略。
- **既有 schema 怪癖**：`renameSession` 用 `settingsFields.model.parse(title)` 校验标题（`src/core/harness.ts:307`）。此复用是否合适需复核；自动命名应使用**真正的** `title` schema（`min(1)/max(256)`）。
- **测试回归**：session 创建相关测试假定 `"New session"`；引入自动命名可能改变列表断言。
- **事件 schema 兼容**：新增事件类型会影响 `agentEventSchema` 的判别联合与所有穷尽 switch（项目要求 `assertNever`），成本需评估。
- **成本与延迟**：每次自动命名都是一次额外模型请求；"每会话一次"是硬约束。
- **并发工作**：工作区存在其他任务的在途改动（Markdown 渲染相关），实现时不得覆盖。
- **本机流程**：按 AGENTS.md，本机 CLI 更新走"改代码 → `node scripts/build-core.mjs` → 重开 `forge`"，不做完整发布/打包。

## 9 验收标准

- **AC-1**：新会话首轮 `completed` 后，若标题仍为默认值，则被自动替换为可读标题。
- **AC-2**：用户手动重命名后，自动命名**不再**改写该标题。
- **AC-3**：模型不可用/超时/输出非法时，降级为启发式标题，**且运行终态不受影响**。
- **AC-4**：每个会话**最多**自动命名一次（含重启后）。
- **AC-5**：桌面侧栏与 CLI `sessions` 列表都能显示自动命名结果。
- **AC-6**：命名请求不写入消息历史、不计入预算、不泄露敏感值。
- **AC-7**：自动化测试覆盖：默认标题判定、用户已改判定、降级路径、只命名一次、锁并发。
- **AC-8**：`pnpm typecheck` 与 `pnpm test` 通过；相关文档同步更新。

- 未评估新增 `title_updated` 事件对既有事件测试与 `assertNever` 穷尽检查的**具体影响面**。

## 11 本轮实施记录（2026-10-14）

采用持久化 titleSource(default/user/auto) + autoTitleAttempted；旧记录缺来源标记保守保留。显式创建标题与 rename 为 user，fork/child 不改。仅 completed 后有用户与助手文本时自动命名一次：先锁内保存首行清洗降级标题及尝试标记，再释放锁调用当前模型（无工具定义，独立 2 秒超时），成功后重新读取并锁内条件提交。下一轮/rename/compact/fork 优先中止后台命名；退出等待其收尾，provider 不响应取消也不会拖住等待。请求不写历史、事件正文或预算，过滤已配置 key、端点和常见 token/URL；不能保证识别用户文本中任意未知秘密。

通知采用宿主重拉方案：桌面 run_finished 后 2.5 秒额外刷新一次（卸载取消），不新增事件；CLI 下次 sessions 刷新可见。极慢存储可能晚于该刷新，需再次刷新。短问候可降级原文。模型输入仅取清洗后的用户/助手各 60 字，是有界摘要而非完整首轮。未配置无法完成主运行时不触发命名。

聚焦单元/真实临时存储集成覆盖一次性、重启、手动保护、并发 rename、连续运行锁、失败降级、无合作 provider 超时、sanitization。尚未真实 API 测标题质量/成本，未新增 title_updated 事件；这不是完整 AC 验收。

## 12 超时调整（2026-10-21）

模型命名的独立超时从 2 秒延长至 30 秒，避免较慢响应过早降级。调用方取消、根运行预算截止、失败保留首条消息标题及每会话仅尝试一次的规则不变；已有尝试记录不会自动重试。
