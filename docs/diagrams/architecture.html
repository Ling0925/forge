Forge：单一共享核心的本地代理 Harness

一个包内同时产出 Node 22 CLI、Electron 桌面工作台、LAN Web 前端三种宿主； 它们调用同一个 HarnessService → AgentRuntime 循环、同一套工具注册表、 同一个会话目录（~/.local/share/forge / $FORGE_HOME）。 CLI 不经过 IPC，桌面不把逻辑放进渲染进程 —— 差异只在“宿主外壳”。

TypeScript ESM · strict Node ≥22.23.1 <23 Electron 44.7 React 19 + Vite esbuild + Vitest + Biome pnpm workspace Zod 边界校验

三条硬约束（源码可验证，是读懂全图的钥匙）：
  • src/shared 不 import 任何 Node/Electron API，也不写文件 —— 它是纯契约层（docs/ARCHITECTURE.md:7 明述）。

04一次 Run 的生命周期

依据 src/core/runtime.ts:440 → 1107 的实际控流绘制。虚线框内是每个 agent turn 都会重入的循环体。

1
取会话锁 → 载入快照

store.acquire() 用 Linux flock -n -E 75；Zod 校验后进入内存；若配置 runMemory 先做冷恢复（闲置 ≥1h / >32 000 token）。

2
孤儿状态收敛

持久化的 running / awaiting_approval 一律改判 interrupted 并落盘；剥离 pendingTool，未闭合调用由 closeCalls() 写入“上次执行被中断，先检查效果再重试”。

3
权限夹紧

plan 模式 → 强制 readonly；否则取 input.permission ?? settings.defaultPermission，再与 session.permissionCeiling 取较低者。运行中经 control.getPermission() 重算（runtime.ts:464）。

4
组装系统指令

buildSystemInstructions() = 核心指令 + # Project context（AGENTS.md + skills 元数据）+ # Current run（workspace / mode / effective permission / maxToolCalls）。纯函数、字节稳定，不改写持久历史。

5
提交用户轮 + 自动标题

追加 user message（可含 images）；claimAutoTitle 抢占式异步起名，仅当标题未被用户改动才应用，并以 title_changed 通知。

6
发布 run_started → 解析上下文窗口

模型以会话持久值为权威，input.model 覆盖只在拿锁后写入；缺失窗口用 2s 超时向 provider 元数据试探，失败不阻塞请求。

循环体 · 每个 agent turn 重入（turn ≤ maxTurns，call ≤ maxToolCalls）
7
drainSteering → 预算判定

先吸收插话。用标定后尺寸（本地字符估计 × 本会话自学的 1.25–2.0 缩放）对比 budget，而不是裸估计。

8
语义压缩 / 整轮硬裁剪

超线 → 找合法 summaryBoundary → summarizeWorkingState() 由 provider 生成 ≤8192 结构化 working state（goal / constraints / decisions / completed / nextSteps / verification / uncertainties + mN 引用），不改持久 transcript，发 context_compacted。兜底 compactContext() 只删完整已闭合轮；放不下则 budget 失败，而不是截断工具 JSON。

9
provider.complete（流式）

context_usage(projected) → 传输。瞬时失败按 RETRY_DELAYS_MS [500,1000,2000,4000,8000] 重试同一请求（不耗 turn、不重跑已完成工具），发 provider_retry；取消经 withCancellation race，绝不重放不确定副作用。

10
tool_call_preview（瞬态）

createToolPreviewStream 只报 previewId / 名称 / argumentsChars / 行数估计；参数片段不过 UI 边界。定稿前 tool_preview_reset。

11
无 tool_calls → 逐级收敛

依次 join：未交付的子代理（以 origin:"agent_reconciliation" 的 user 消息注入有界报告）→ 后台命令 settleBackground() → 最终 steering 队列；三者皆空才 finish("completed")。

12
有 tool_calls → 串行执行

先校验 call id 唯一；逐个：pendingTool 落盘 → tool_started → 审批（先置 awaiting_approval 落盘，approval_requested 经队列串行化）→ native 或 registry 执行 → 结果与 FileChanges 落盘 → tool_finished。被拒也算一次 attempt。

13
每个交换都 checkpoint

执行前 checkpoint 调用、执行后 checkpoint 结果/变更，副作用经 serialized() 串行；写/编辑额外生成文件级私有备份（命令效果不进备份）。

14
唯一终态 → 释放

run_finished(completed / cancelled / failed) 恰好一次；预算耗尽先 error(code=budget) 再终态；子代理有未处理失败时父的 completed 降级为 failed。finally 里释放会话锁、dispose run 级工具与 ProjectContext。

事件 vs 持久化

text_delta / reasoning_delta / tool_call_preview 是瞬态通知（EventSink 同步、无背压，宿主自行限制缓冲）；只有归一化的最终 assistant 消息进入 transcript，失败或被取消的部分回复压缩为一条有界历史事件。

设置与会话的边界

run 边界捕获公共设置与私有 provider 配置；设置变更不影响进行中的 run。settings.model 只影响新会话，恢复的会话坚持自身持久模型；锁获取失败或启动前被拒则不得改动会话模型。

宿主侧审批策略（与 Permission 分离）

CLI · full-access（默认）

DEFAULT_APPROVAL_MODE（approval-policy.ts:5）。在既有权限边界内自动应答审批请求，含 MCP / 浏览器 / 子代理。启动与切换都有可见警告；自动应答输出 tool/argv 审计行并脱敏常见凭据。

CLI · auto

只对根 run 的 run_command 这类合格请求自动放行（存在 childSessionId 不自批）。非交互 run / resume 仍需显式 unrestricted + --yes。

CLI · manual（别名 ask）

逐次 Approve? [Y/n]。只有新鲜未被污染的回车或 y/yes 才算批准：粘贴、队列消息、历史输入、Esc、abort、EOF 一律不能授权。

桌面 / Web

审批走 approval_requested 事件 + Inspector 面板按钮，answerApproval(runId, approvalId, approved) 匹配后只解析一次。false 即拒绝；无自动应答。

审批模式只对当前 CLI 进程生效（/new、/resume 后仍保持），不写回全局设置。 任何模式都不是 OS 沙箱、也不是权限提升 —— 工具自身的路径 / origin / 注册状态 / 子代理 ceiling 检查始终生效。unrestricted 只是刻意放宽策略，不是解除守卫。

07子代理编排

主代理 run ──spawn_agent──▶ 子会话（独立 Session）
                              · 独立 context / session / model / tool registry
                              · depth 1（子不能再 spawn）
                              · 每 run ≤4 活动槽，总量 ≤32
                              · permissionCeiling = 继承父级上限
                              · 父 plan 模式 → 子继承 readonly

        ├── send_agent_message  排队提示（≤8 条），仅下个模型边界生效，非中断
        ├── list_agents         currentRun / active / controllable 区分历史记录与本地所有权
        ├── wait_agents         all | any · timeout_ms ≤120 000；超时不取消工作
        ├── get_agent_result    有界分页读最终报告（UTF-16 偏移，先脱敏）
        ├── cancel_agent        取消并 join（不清除失败事实、不动兄弟任务）
        └── resolve_agent       父检查效果后记录“已处理”的具体依据

父终态：join 全部子 → 未交付报告以 agent_reconciliation user 消息注入
        → 有未处理失败 ⇒ completed 降级 failed（阻塞父成功）
事件边界

只有 parent-scoped 的 agent_update 信封外发；子的原始事件不转发。子的审批用根 sessionId + 原子 toolCallId + 请求 UUID，并串行化在父的审批队列里，避免 UI 交错。

对账消息是本地元数据

origin:"agent_reconciliation" 只存在于 user 消息（schema 唯一接受处），provider 上线前剥离；它不算人类轮（isHumanTurn 排除），轮次边界与渲染层折叠都按内部记录处理。

模型选择纪律

list_models 只证明目录成员资格，不证明配额或可用性；换模型不自动重试、不 fallback、不重放有副作用的任务。本仓库 AGENTS.md 进一步把子代理模型固定为 cbcn/deepseek-v4.1-flash。

失败恢复

父 run 结束或进程重启会留下记录但不恢复任何子任务（无跨 run 恢复）；后台命令任务同样在父终态时被 join，未检查的输出不会静默丢失成孤儿进程。

Journal 的换 base 规则

64 条 delta / 4 MiB / run 终态 → base 原子替换并换 generation ID，因此被保留的恢复记录不可能在被打断的 checkpoint 之后二次应用；未提交的临时文件被忽略。混用新旧可执行文件是被禁止的：旧严格读会拒绝新的私有 base 标记，而不是把陈旧 checkpoint 当完整历史打开。

IO 底座（store/io.ts）

privateDirectory() 递归拒绝祖先 symlink、校验并强制 mode 0700；atomicJson() = 临时文件 + fsync + rename + syncDirectory；快照上限 64 MiB。列表读到坏记录只跳过该文件，不阻断健康会话访问。

Checkpoint ≠ git

begin/complete/release 只覆盖 write_file / edit_file 等直接文件编辑；run_command 效果不进检查点，FileChange 预览也只是预览。恢复要求：单个 checkpoint + 单文件、状态 completed、会话非活动、当前字节与权限模式等于记录的 after-hash —— 冲突即拒绝，从不做 git reset。getCheckpointDiff RPC 上限 256 KiB。

锁的语义

runtime 持有跨进程会话锁直到最后一次 checkpoint，finally 释放；并发获取失败返回 busy 而非静默交错；取消不泄漏锁；harness 不再包第二层锁。孤儿 running 快照在锁内恢复为 interrupted。

Provider source 归属

providerSourceId 属于会话：创建时捕获所选源，fork 与子继承。删除源不得孤立会话 —— 设置存储会反查仍引用该源的会话 ID 列表（harness.ts:128）。

压缩管线（三级）

A
标定估计

seedContextScale() 取本会话持久事件里 projected → reported 比率的中位数，夹在 1.25 … 2.0；长会话恢复时不必每次重新学习，一次异常轮次也无法扭曲它。

B
语义摘要

provider 生成 ≤8192 的结构化 working state（6 类条目 × ≤12，每条带 mN 引用，整体 ≤6000 字符）。稳定 system 前缀保持；持久 transcript 不被改写，只推进 contextSummary.boundary。

C
整轮硬裁剪

compactContext() 保留指令与当前请求，只删除完整已闭合轮次及其工具交换；遇到无法归属的 tool result 或未解决原生调用 → 以 budget 失败。若最近三轮本身就超硬预算，则保留更少整轮而非丢弃语义。excerpt-only 兜底会标记 contextSummary.fallback。

压缩后的 working state 自我标注为部分摘录、非穷尽覆盖，并指示用 history_search / history_read（mN 记录）取回原始证据 —— 而不是把摘要当完整历史。
为什么必须标定：实测 788 个轮次中，真实输入约为裸字符估计的 1.16×（p50），工具结果密集或 CJK 时 >1.4×（p90），而裸估计从未越线 —— 只用原始估计会让请求在已超窗之后才触发裁剪。

Fork · Compact · Resume 的差异

操作做什么硬约束
forkSession(id, boundary?)复制历史生成新会话（继承 providerSourceId 与 ceiling）只复制，绝不执行复制来的调用；边界须通过 assertBoundary 的完整原生调用对校验；仅当源 summary 边界 ≤ 请求边界且在副本中构成完整原生边界时才保留 contextSummary，更早的 fork 省略以免导入未来历史；持久 ProviderState 续写上限 256 项 / 256 KiB
compactSession(id)宿主显式触发语义压缩transcript 不变，只推进摘要边界；provider 生成失败可用有界 excerpt 兜底并标注 fallback
run / resume在同一 store 上继续会话必须先报告不确定效果并安全清理 pending 状态；显式 resume 要求历史已 settled
冷恢复 session-memory闲置 ≥1h 或 >32 000 token 时留下可恢复的最近状态sourceHash 覆盖 messages / plan / contextSummary / status / 最后 run_finished，指纹不符即不套用
