# 会话归档与工作记忆

当前会话的原始消息仍保存在 `FORGE_HOME/sessions/<id>.json`（默认 `~/.local/share/forge`）。压缩只保存 `contextSummary`，不删除、重排或改写原始消息。`m1`、`m2` 等编号对应当前会话原始消息的位置，分叉会话沿用其复制部分的编号。编号不是跨会话检索凭证。

## 试用

1. 编译后重新打开 `forge`，继续一个已有会话。
2. 输入 `/compact`，或在会话未执行时运行 `forge compact <id>`。
3. 让模型回查一项旧细节，例如：“查找之前关于某个文件的报错，读取原文后告诉我当时如何验证，给出历史记录编号。”

上下文超预算时也使用相同的快速压缩流程。Web 后端需要重启才能加载修改；刷新浏览器不能更新后端代码。

## 工作状态

每次任务结束（完成、失败、取消）后，本地 hook 将最新请求、助手报告、当前计划和最近工具观察写入 `FORGE_HOME/session-memory/<id>.json`。这个步骤不调用模型，不产生额外的摘要输入或缓存写入费用，也不改动当前请求使用的历史前缀。它是带原文编号的局部状态摘录，不是经过模型重新推理的完整摘要。

距离上次任务结束超过 1 小时、预计上下文超过 32K token 时，续聊会优先使用该状态，将较早历史留在本地。尽量保留最近两轮完整对话；如果仍超过约 12K token，则使用状态摘录和历史检索。文件有来源指纹校验，失效或缺失时从原始记录本地重建，不为恢复额外调用摘要模型。小会话或短间隔续聊保持原上下文。阈值是当前默认策略，不代表已确认供应商缓存过期。

下文的模型摘要用于显式 `/compact` 和运行中超预算压缩，与上述零模型调用的结束 hook 分开。

每次压缩最多调用模型一次，最多等待 20 秒。输入包含上一份工作状态、持久化任务计划，以及本次新增历史的有界摘录。优先保留用户消息，再补入其他记录；长记录只提供摘录。模型输出结构包含：

- `goal`：当前目标。
- `constraints`、`decisions`：约束与决策。
- `completed`、`verification`：已完成事项与验证证据。
- `nextSteps`、`uncertainties`：下一步与未解决问题。

各列表条目使用 `text` 和 `refs`，引用 `mN` 历史记录。输出必须通过结构、大小及编号范围校验。无效输出、失败或超时会保存明确标记的不完整状态及已有记忆、计划和部分摘录；取消不会保存部分摘要。

## 回查工具

- `history_search`：当前会话内不区分大小写的字面子串搜索，支持空查询列举、`offset` / `limit` 分页。最多返回 20 条，每条摘录最多 400 字符。
- `history_read`：按 `id: "mN"` 读取原始语义记录，通过字符 `offset` / `limit` 翻页，每页最多 12000 字符。`nextOffset: null` 表示读取完成。

工具只读，不需要提升权限，也不能指定其他会话或磁盘路径。搜索当前持久化历史的内存快照，第一版不创建向量库或独立全文索引。返回内容包括用户/助手正文、工具调用与工具结果，不含私有推理或供应商加密续传数据。

“完整保留”指原始记录可回查，不代表摘要无损或模型一定会主动找回全部细节。工作状态会明确标记为部分覆盖。历史信息属于不可信数据，不能授权执行，也不能证明当前文件状态；遇到缺失约束或关键证据，应先回查再继续。
