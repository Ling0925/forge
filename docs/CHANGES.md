# Changes

- Tool-argument streaming previews now also carry a live change-size estimate for the file-writing tools. `toolCallPreviewSchema` gained optional bounded `linesAdded`/`linesRemoved` (0–1,000,000), and the `tool_call_preview` run event forwards them. `src/shared/tool-preview-lines.ts` derives them from the *incomplete* arguments string without parsing JSON: a small scanner walks the top-level object, tracks string boundaries and escapes, and counts newlines (escaped `\n` and raw newlines) in `content` for `write_file`, and in `new_text`/`old_text` for `edit_file`; an empty body is 0 lines, otherwise newlines + 1. It stops at the first malformed or truncated token instead of guessing, ignores nested or unrelated keys, and every other tool keeps the fields undefined. All three adapters pass the accumulated fragment to `notifyToolCall` (Chat Completions deltas and non-streaming JSON, Responses `function_call_arguments.delta`, Anthropic `input_json_delta`), so only the two counters leave the provider — never argument text. `createToolPreviewStream` now also treats a change in either estimate as a real update, and `runtime.ts` forwards both fields on the ephemeral event; they still never enter the stored transcript. Covered by `tests/shared/tool-preview-lines.test.ts`, new cases in `tests/provider/tool-preview.test.ts` and `tests/provider/anthropic.test.ts`, and new stream/runtime cases in `tests/core/tool-preview.test.ts`. Not verified: real provider streaming against a live gateway, and estimates for multi-line content split across unusual escape sequences.

- Automatic context compaction now triggers on a calibrated context estimate instead of the raw local estimate. `measureContext` is a character heuristic, not the provider tokenizer: across every recorded session in `~/.local/share/forge*/sessions` real input ran at ~1.157x the estimate (p50) and ~1.444x (p90), so the old raw comparison let 800 recorded turns exceed the 80% trigger while the raw estimate never once crossed it — the trigger fired late, trimmed too little, and long sessions grew toward the model window. `src/core/runtime.ts` now multiplies the estimate by a scale learned per run from the provider's own reported input (seeded from this session's persisted `context_usage` pairs via `seedContextScale`, so a resumed session starts calibrated), bounded to `[CONTEXT_SCALE_FLOOR, CONTEXT_SCALE_CEILING]` = `[1.25, 2]` and only ever raised within a run, so one light turn cannot mask a heavier one. The trigger, the summarization target and the hard trim all use one unit again (`rawLimit`/`rawTarget`), so the request that leaves Forge is the one measured against the budget. Covered by two regressions in `tests/core/runtime.test.ts` (seed bounds/median, and a long CJK run whose every request stays inside the real window). Not verified: real provider end-to-end behaviour, non-CJK distributions, and the 300K default window for unknown models.

- Web UI can now preview HTML. A fenced code block tagged `html`/`htm`/`xhtml` gets a 「预览」 action, and a changed `.html`/`.htm` file gets 「预览 HTML」 in its diff card header. Both open a dialog with a real rendered page. Because the workbench CSP refuses `srcdoc`, `blob:` and `data:` frames, the Web backend serves each document from its own authenticated URL (`POST /api/preview`, `POST /api/preview/file` → `GET /preview/document?id=…`; 24 random-byte ids, newest 24 documents / 30 min / 8 MiB). The frame is `sandbox="allow-scripts"` without `allow-same-origin`, so preview scripts cannot read the workbench DOM, its session cookie or workspace files, and the document CSP (`default-src 'none'`, `connect-src 'none'`, `form-action 'none'`, data/blob-only media) blocks network access. File previews go through the workspace path guard (no traversal, symlinks, hidden paths, non-HTML, non-UTF-8 or >1 MiB files). The desktop Electron bridge has no such endpoint, so the shared renderer simply hides the buttons there. Covered by `tests/renderer/html-preview.test.ts`, `tests/renderer/html-preview-mounted.test.ts` (real Chromium: opaque-origin frame, blocked parent access, blocked network, unmount on close) and a new `tests/web-host.test.ts` case.

- Fixed a bogus "（无行级差异）" in file diffs. `FileChange.before/after` are only the first 8192 characters of each side (`PREVIEW_LIMIT`); when an edit lands beyond that window both previews are identical, so the renderer wrongly concluded there was no change. The renderer now renders `change.patch` — the exact hunk diff the tools already compute from the full originals (and the CLI already uses) — and only falls back to the previews when no patch was recorded. Unknown content is labelled ("无文本改动" vs "精确差异不可用") rather than reported as zero, and the header +/- counts now come from the same patch. Also aligned the shared patch context to 5 lines (`src/shared/diff.ts`). Covered by a regression in `tests/renderer/tool-disclosure.test.ts`.

- A file-edit card now shows only the diff: the raw "参数输入" rows ("原内容"/"新内容") are dropped for `edit_file`/`write_file`, since they merely duplicated the comparison. The card header now shows colored line counts — green `+N` added and red `-M` removed — computed from the same real alignment (`diffStats()`), summed across the tool's changed files. Covered by `tests/renderer/tool-disclosure.test.ts`.

- The file diff no longer shows the whole file. `DiffViewer` now aligns lines properly (trim common prefix/suffix, then a bounded LCS over the middle), so a mid-file insertion is one added line instead of marking every following line as changed. Rendering keeps only the changed lines plus ±5 context (`DIFF_CONTEXT_LINES`); skipped unchanged runs collapse into a single "⋯ 已省略 N 行未改动内容 ⋯" separator. The 10-line preview and expand control are unchanged. Covered by `tests/renderer/tool-disclosure.test.ts`.

- Tool cards were simplified for readability. A `run_command` card now opens by default and shows only the executed command and its raw result — the parsed "参数输入" rows and parsed result key/value rows are gone, since they duplicated the command line and made the card look cluttered. A file-edit card (`edit_file`/`write_file`) still opens by default but its diff now previews only the first 10 lines (`DIFF_PREVIEW_LINES`) behind a "展开全部差异（还有 N 行）" control; expanding reveals the rest inside a bounded scroll region. Covered by `tests/renderer/tool-disclosure.test.ts`.

- The shared renderer (Electron desktop + Web dev) now renders model reasoning as a bespoke, non-native component instead of a browser `<details>`. While the model thinks, `Reasoning` shows a "思考中" header with a fixed 5-line auto-scrolling viewport that keeps only the newest lines, so a long thought no longer reflows the whole transcript. Once the thought ends it collapses to a single last-line summary (one compact history row) that can be clicked to reveal the full reasoning. `Transcript` renders `run.pendingReasoning` (saved-but-unsynchronized) and the live `run.streamingReasoning` above the answer; reasoning deltas count as arriving content for follow-scroll. Previously the reducer captured `streamingReasoning`/`pendingReasoning` but the UI rendered neither, so Web/desktop showed no live thought text (only the CLI had the single-line `✻` preview). Covered by `tests/renderer/reasoning-mounted.test.ts` (live viewport present and scrolled to the bottom, no native `<details>`, ends as a one-line summary, click expands, persisted reasoning is its own summary). Not verified: real provider end-to-end reasoning streams, narrow/high-contrast/screen-reader matrices, and true >131072 truncation.

- CLI shows a single-line, scrolling preview of live model reasoning when the gateway streams it: Chat Completions `reasoning_content` and Responses `reasoning_summary_text.delta`. The preview is now **persisted** on the assistant message's optional bounded `reasoning` field (128 KiB cap), so `forge resume` / `--session` rebuilds the same `✻` line from saved history. It stays display-only: never folded into assistant content, never present in the event log, and never sent back to the provider. Chat Completions streaming requests now send `stream_options.include_usage` so spec-compliant gateways report this request's real usage (including cache hits) inside the stream, letting the context footer update the cache rate on every model request instead of only at the end of a run.

- Added private, persisted per-file tool checkpoints for native `write_file` and `edit_file` when a `checkpointStore` is configured. Backups store full bounded original/result bytes and SHA-256 hashes outside the workspace; preview text is not a backup. Restore checks active session and exact current hash, supports created-file removal, and rejects symlink/path escapes. Pending records remain non-restorable.
- Registered native read-only `git_status`, `git_diff`, and `git_log` tools, including in readonly mode. Git inspection refuses repository fsmonitor hooks/external diff and other executable configuration, omits forbidden paths, redacts known values, bounds output, and reports omissions. Git observations are not tool checkpoints. No automatic git initialization or commits.
- Git diff now forces literal pathspec interpretation for tracked filenames, preventing a filename such as `:(glob)*` from expanding a permitted per-file diff to forbidden `.env` blobs. A real temporary-repository regression covers pathspec magic, leading dashes, newlines, and honest omissions.
- Executable file modes are preserved through native replacement and checkpoint restore. Completion verifies the actual resulting file hash; Unicode diff previews are byte-capped with an explicit truncation marker. Regression tests cover failed backup storage, false completion, external edits, symlinks, cancellation, reload, and full originals beyond previews.
- Integration: hosts integrate the exported checkpoint APIs directly; coordinator-local
  `.build/` contract notes are **not shipped** and are not required reading. Existing local registry without a configured store remains legacy/nonreversible; hosts must supply a private store for reversible edits. Hosts must hold a cross-process session exclusion lock for the entire restore; a single active-session query is insufficient.
