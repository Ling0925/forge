## 1. 设计定位与美学哲学

Forge CLI 摒弃了传统终端工具常见的“粗暴字符堆叠”或“Curses 时代重叠边框牢笼”的做法，呈现出一种**现代、精密、沉静且高度克制（Quiet Precision）**的专业工作台风格：

1. **以排版为界面（Text-as-Interface）**：
   - 彻底淘汰卡片套卡片与全包裹外框，依靠严格对齐的缩进（2 空格 / 4 空格）、字重层次、微弱细线（`─` / `│`）以及垂直呼吸感来构建视觉层级。
   - 启动区域保持极简（4 行元数据），迅速退居后台，将终端主舞台完全留给人类与模型的任务对话。
2. **桌面端与终端视觉心智同构**：
   - 与 Electron 桌面端（Warm Light-First Minimal Workbench）保持同源语法。
   - 桌面端的“一体化圆润输入舱（Composer）”在终端降维为底部的交互式 Dock；桌面端的“水平静默工具行（Quiet Tool Rows）”在终端转译为 2 行折叠式紧凑工具卡片。
3. **现代底层协议保障质感**：
   - 依托 Synchronized Output（`\x1b[?2026h`）与增量差分比对绘制（Delta Painting），消除了终端流式输出与光标高频移动时的刷新闪烁与撕裂感。
   - 依托字素簇（Grapheme Clusters）与 East Asian Width 列宽计算，实现 CJK 中文字符、Emoji 与等宽英文字符的严密物理网格对齐。

## 2. 现行美学体系剖析

### 2.1 色彩语义与对比度控制
* **告别高饱和“黑客绿/冷蓝”**：
  采用针对浅色（Light-First 米白画布）与深色（暖炭黑画布）专门调配的 Truecolor（24-bit）及 256 色阶色彩系统（`src/cli/theme.ts`）：
  - **强调色（Accent）**：沉稳典雅的鼠尾草绿（Light: `#55684d` / Dark: `#8fad82`），用于品牌标题、当前正在运行的工具名与模型名称。
  - **辅色（Muted）**：经过实测对比度 ≥ 4.5:1 的灰绿色调，用于时间戳、路径元数据、参数注释，绝无刺眼白色或不可辨别的死灰色。
  - **状态色（Success / Warning / Error）**：饱和度经过审慎衰减的草木绿、琥珀黄与柔和珊瑚红，只在执行成功、审批拦截/Plan模式切换以及错误中断时作为关键信号点缀。
* **语义脱钩原则**：
  颜色仅作为增强认知手段，关键状态（Done / Failed / Running / [Y/n]）始终伴随文字与图形标记（`❯`、`⠋`、`+ / -`），保证在 `NO_COLOR` 或 `TERM=dumb` 场景下信息完整表达。

### 2.2 信息密度与界面组件美学
* **多维度上下文光谱条（Context Footer）**：
  - 在底部 Dock 仅占用 2 行：第一行展示模型与实报缓存命中率（如 `≈50.0% · R90% · 128k`），第二行采用字符点阵将系统指令、记忆、对话、工具四类 token 渲染为四色分段光谱条，并在右侧标出预算压缩警戒红线。
  - 终端高度受限时（≤ 20 行）自动收缩为单行迷你仪表条（`[━━··]`），信息密度与现代仪器仪表质感兼备。
* **静默紧凑工具卡片（Quiet Tool Cards）**：
  - 默认折叠态为两行：工具名/目标/耗时（毫秒级递进） + 核心摘要；
  - `edit_file` 原生内嵌最多 18 行的精细 Myers diff 预览（带首尾增删行高亮与截断提示），既直观展现代码变更事实，又杜绝了数百行原始输出刷屏破坏上下文。
* **出版级 Markdown 排版**：
  - 基于 `marked` + `marked-terminal` 实现完整的 GFM 渲染；
  - 代码块以极简细线划分（`── typescript ──`）配合轻量语法着色（`cli-highlight`）；
  - 宽表格或超多列表格自动降级为清晰的键值行组排版，根除横向折行排版崩溃。

## 3. 下一阶段体验与美学进阶建议

为使 CLI 的操作体验与细节完成度达到极致，提出以下三类进阶优化提案：

### 3.1 视觉层次与闭环感（Visual Polish）
1. **代码块底部轻量闭合（Code Block Closure）**：
   - *现状*：长代码块顶部有语言标识线，底部仅靠换行收尾。
   - *提案*：在代码块尾部增加一条柔和的收束底线（如 `────────────────────────────────────────`），在长篇代码滚动翻页时提供清晰的段落终点视觉锚点。
2. **工具头部 Diff 统计徽章（Diff Stat Badge）**：
   - *现状*：`edit_file` 展示局部 diff，但未在工具行直接体现变动规模。
   - *提案*：在工具头部增加 Git 风格的变更统计标签，如 `edit_file src/cli/view.ts [+18 -4] · done (120ms)`，大幅提升快速扫视效率。
3. **浮层选择器的分页/未显示项微标（Continuation Cue）**：
   - *现状*：`/model` 与 Slash 命令菜单在超出可视行数时截断。
   - *提案*：在列表底部显示 `… 还有 12 项 (输入过滤，↑/↓ 翻页)` 或在右侧边缘加入极简的单字符滑块指示线（`┃` / `┆`）。

### 3.2 交互反馈与状态感知（Feedback & Ergonomics）
4. **浏览历史视口的浮动引导（Scrollback Indicator）**：
   - *现状*：向上滚动浏览历史时，界面能正确锁定视口，但用户缺乏“当前位于历史哪一段、下方有无新内容”的直观反馈。
   - *提案*：当 `scrollOffset > 0` 时，在输入框上方以弱色浮现微胶囊：`▼ 正在查看历史 (距底部 18 行) · 按 End 或空输入按 Esc 归位`。
5. **OSC 52 剪贴板复制成功微反馈**：
   - *现状*：鼠标拖选后按 `Ctrl+C` 触发剪贴板复制，但部分终端不支持或静默处理。
   - *提案*：在状态栏或浮层中给予定时 1.5 秒的微提示（如 `✓ 已复制 8 行到剪贴板`），建立明确的交互确定感。

### 3.3 编辑手感与高级场景（Composer & Workflow）
6. **规避 `Shift+Enter` 误发送的换行与外部编辑**：
   - *现状*：部分终端不支持独立 Shift+Enter 键码，易将换行当作回车提交。
   - *提案*：
     - 支持标准的 `Alt+Enter`（`\x1b\r`）强制插入换行；
     - 提供 `/edit` 命令，临时调用 `$EDITOR`（如 Nano、Vim 或 VS Code）撰写长篇复杂 Prompt，退出后回填到当前输入框。
7. **Readline 习惯全面对齐**：
   - 补齐终端老手高频依赖的 `Ctrl+K`（剪切光标至行尾）以及 `Alt+B` / `Alt+F`（按单词前后跳跃）。

## 4. 边界与设计底线（Guards & Boundaries）

任何美学与视觉优化均须服从以下既有契约：
- **无障碍门禁**：正文与图标保持 ≥ 4.5:1 对比度，重要图形边界 ≥ 3:1；严禁纯靠颜色传递单一关键信息。
- **真实证据原则**：文件修改、耗时、退出码与差异比对必须来自底层事实，严禁为追求界面美观而伪造阶段或抹平错误提示。
- **环境韧性与渐进增强**：
  - 在 Truecolor 环境展现细腻的鼠尾草绿与暖色调；
  - 在 256 色环境中优雅降级到近似安全色；
  - 在 `NO_COLOR` / `TERM=dumb` 下彻底剥离 ANSI 样式，保留清晰结构化的纯文本输出。
