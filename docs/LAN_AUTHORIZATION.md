# LAN 直接接入

Forge 的 Web、dev 和桌面 LAN 是个人局域网入口。开启监听后，手机扫码或打开地址即可连接同一个核心；不需要邀请码、设备授权、本机 CLI 配对或现场确认。首次连接、换浏览器、清除 cookie 后连接和日常重连都使用同一条直连路径。

## 使用方式

- 桌面：开启 LAN 监听，Android 扫码或输入公开地址；以后使用已保存地址重连。
- 独立 Web：`pnpm serve:web --host 192.168.1.2 --port 5173 --workspace /project`。
- 开发服务：按 [Web 开发](WEB_DEV.md) 启动后直接打开地址。
- 不再需要 `--trusted-lan` 或 `FORGE_TRUSTED_LAN=1`。旧开关不再改变这些入口的行为。
- 宿主需保持运行，网络需可达；跨网访问由用户自行配置 Tailscale 等工具，不内建公网中继、穿透或云账号。

## 保留的边界与生命周期

网络可达范围由用户管理，能够访问监听端口的设备可以使用工作台。HTTP 不提供传输保密性，不应把端口直接公开到互联网。

这次恢复直连不改变核心的工具权限、审批设置、工作区范围、文件路径/符号链接和附件所属会话检查。Host/Origin 校验、JSON POST、请求大小限制、WebSocket 页面标识与事件游标也保持原有行为；没有新增手机端审批。

页面断连或停止 LAN 监听**不取消已被核心接受的任务**。`web.close()` 只关监听；核心所有者的 `dispose()` / 进程退出才结束其运行。需要停止任务时使用原有运行控制，不会因连接消失而自动批准、重放或取消操作。

## 历史设备授权代码

设备存储与 `forge devices` 命令保留以兼容已有开发接口，正常 Web/dev/桌面 LAN 入口不使用它们，也不会因为旧授权记录缺失、损坏、过期或被撤销而阻止直连。只有自定义宿主在代码中明确传入 `trustedLan: false` 才使用该底层授权模式；它不是手机接入的前置步骤。此变更不删除现有设备记录。
