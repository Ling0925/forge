# 当前会话变更审查

在已有会话中输入：

```text
/review
/review 重点检查权限边界、错误处理和兼容性
```

CLI 和桌面/Web 共用命令表与审查上下文构造器。`/help` 和输入 `/rev` 的补全列表均可发现命令。补充重点可省略，最多 8000 字符；参数沿用斜杠命令的空白分词规则。

## 模型与运行

- 沿用当前选择的模型及来源；桌面选中路由组时沿用该组。CLI 可先用 `/model` 切换。不引入独立审查模型，也不新建子会话。
- 在原会话追加一轮审查，使用现有流式输出、持久化、错误处理和取消机制；会产生正常的模型调用与用量。
- 本轮以 `build + readonly` 运行：任务是输出审查结论，不是生成实施计划；文件写入和命令执行受现有只读策略限制。不会自动修复、提交、恢复检查点或委派其他模型。下一轮的模式、权限与审批设置不变。
- 需要已有会话。无会话时先发送消息、`/new` 或 `/resume`，命令不会偷偷创建空会话。
- CLI 运行中输入 `/review`，沿用已有命令队列，在当前运行结束后获取最新会话并执行；Ctrl+C 可取消准备/审查。桌面运行中明确拒绝，不自动排队；准备期间切换会话不会在旧会话或新会话误启动审查。

## 审查范围与证据

主要证据是完整会话保存的原生文件变更记录（`SessionSnapshot.changes`），因此提交到 Git、压缩上下文或恢复历史会话后仍可审查，不依赖当前 `git diff` 是否为空。不会将工作区的所有未提交文件直接归为当前会话的变更。

提供路径索引和按发生顺序排列的历史补丁，同一文件的多次修改不会拼成虚假的净差异。要求模型重新读取当前文件、关联调用方和测试，排除已回退/修复的问题与其他人的改动。输出按严重程度列出问题、路径/行号、影响和简短建议；无明确问题、证据不足和未执行测试均应如实说明。

诚实边界：

- 命令、生成器、格式化、检查点恢复、子代理等操作不一定产生原生文件变更记录。提示模型使用 `history_search`/`history_read`、子任务报告与只读 Git 信息补查归属；缺少原生记录不等于没有变更。
- 路径索引和补丁有上下文预算，超出时显式说明省略数量；优先携带最近操作的补丁，保留原补丁的 `complete`/`truncated`/`unavailable` 标记。不把部分证据说成完整覆盖，也不把历史内容说成当前文件状态。
- 本轮不执行测试或构建，只能引用已有验证记录并做静态审查。模型审查不保证发现所有问题；想修复或运行验证，请另行发起正常任务。
